# RAMS JSON API

RAMS exposes a read-only, versioned JSON API for external integrations such as
FAIR Station.

Everything lives under the base path `/api/v1`.

## Authentication

The API uses Bearer tokens issued to an `ApiClient` record — one record per
integrating application.

### How tokens work

- A token is generated by the application when an `ApiClient` is created, and is
  printed exactly once.
- Only a SHA-256 digest of the token is stored (`api_clients.token_digest`). The
  plaintext token is never persisted, so it cannot be recovered later.
- Tokens look like `rams_` followed by a URL-safe random string.
- A client can be deactivated by setting `active` to `false` on its `ApiClient`
  record.
- Tokens can be rotated with `ApiClient#rotate_token!`, which issues a new token
  and invalidates the previous one.

## Scoping

An `ApiClient` may optionally belong to a `Reserve`. Scoping only limits what a
client may read; it never widens it. A client with no reserve is a platform-wide
integration, while a client with a reserve is limited to that reserve's
research.

## Creating an API client

Use the `api:clients:create` rake task. It prints the token once; store it in
the integrating application's secret store.

```bash
# Platform-wide client (all reserves)
docker compose exec web env NAME="FAIR Station" bin/rails api:clients:create

# Client scoped to one reserve
docker compose exec web env NAME="FAIR Station (Valentine)" RESERVE_ID=3 \
  bin/rails api:clients:create
```

Outside Docker, drop the `docker compose exec web` prefix:

```bash
env NAME="FAIR Station" bin/rails api:clients:create
```

Output:

```
Created API client 1 (FAIR Station)
Token: rams_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

## Endpoints

### `GET /api/v1/projects`

Returns the projects visible to the client.

Query parameters:

| Parameter | Default | Notes |
| --- | --- | --- |
| `page` | `1` | Page number. |
| `per_page` | `25` | Items per page, capped at `100`. |
| `status` | (none) | One of `open`, `closed`, `incomplete`. An unknown value returns `400`. |
| `project_type` | (none) | One of `research`, `class`, `meeting`, `public_use`, `housing`. An unknown value returns `400`. |
| `reserve_id` | (none) | Restricts results to a single reserve, within the client's scope. |

```bash
curl -H "Authorization: Bearer $RAMS_API_TOKEN" \
  "https://example.com/api/v1/projects?status=open&per_page=50"
```

### `GET /api/v1/projects/:id`

Returns a single project. A project outside the client's scope returns `404`.

```bash
curl -H "Authorization: Bearer $RAMS_API_TOKEN" \
  "https://example.com/api/v1/projects/42"
```

### Project fields

Fields are explicitly allowlisted; database columns are never exposed by
default.

| Field | Notes |
| --- | --- |
| `id` | RAMS project ID. |
| `type` | Always `"projects"`. |
| `title` | |
| `status` | Enum key: `open`, `closed`, or `incomplete`. |
| `project_type` | Enum key, e.g. `research`, `class`, `meeting`, `public_use`, `housing`. |
| `abstract` | |
| `discipline`, `discipline_other` | |
| `keywords`, `taxonomic_keywords` | |
| `thesis_title` | |
| `course_title`, `course_number` | |
| `start_date`, `end_date` | ISO 8601 dates, or `null`. |
| `submitted_at` | ISO 8601 timestamp, or `null`. |
| `reserve` | `{ type, id, name, short_name }`, or `null` for projects with no reserve. |
| `owner` | `{ type, id, full_name, orcid }`, or `null`. |
| `applicant` | `{ type, id, full_name, orcid }`, or `null`. |
| `created_at`, `updated_at` | ISO 8601 timestamps. |

`status` and `project_type` are returned as Rails enum keys (lowercase), which
match the values accepted by the corresponding query parameters.

## Response format

Collection responses use a `data` + `meta` envelope:

```json
{
  "data": [ { "id": 42, "title": "...", "...": "..." } ],
  "meta": {
    "page": 1,
    "per_page": 25,
    "total_pages": 4,
    "total_count": 87
  }
}
```

Single-resource responses use `data` only:

```json
{ "data": { "id": 42, "title": "...", "...": "..." } }
```

Endpoint payloads are built by presenters, which allowlist the fields they
expose and embed related records as entity stubs (`type`, `id`, and a short
label) rather than full objects.

## Errors

Errors are returned as JSON with an `error` key:

| Status | Body | Cause |
| --- | --- | --- |
| `401` | `{ "error": "unauthorized" }` | Missing, malformed, unknown, or deactivated token. |
| `404` | `{ "error": "not_found" }` | Unknown record, or a record outside the client's scope. |

A `401` response includes a `WWW-Authenticate: Bearer realm="rams-api"` header.

Endpoints that accept filters may also return `400 bad_request` with a
`detail` explaining the rejected parameter.

## Pagination

Collections use offset pagination (`page` / `per_page`, capped at `100`) and are
ordered by `created_at` descending with `id` as a tiebreaker, so page boundaries
are deterministic. Offset pagination can still drift if records are created
while a client is paging; move to keyset pagination keyed on `(created_at, id)`
if that becomes a problem.

Endpoint controllers supply their own ordering via the `paginate` helper on
`Api::V1::BaseController`.

## Not yet implemented

- Write endpoints (the API is read-only).
- OAuth2 / Doorkeeper. Authentication is isolated behind
  `Api::BaseController#authenticate_api_client!`, so Doorkeeper can replace the
  token check without changing endpoint controllers.
- Rake tasks for rotating or deactivating clients (the model supports both).
- Rate limiting.
